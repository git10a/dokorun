# 大会コース・GPX・ランナーの体験：初回実装

2026-10-12。**同日に本番反映済み**（本番アカウント hinode.run の Worker `dokorun` 版 `b4c2ba41`、コミット `dcdb54a`。本番D1 `dokorun-db`(cafb425e…) に `scripts/sql/2026-10-12-race-reviews.sql` を適用。0%→10%→100%で公開）。以下は実装時点の記録。

## 変更内容

- トップ・大会一覧・大会詳細・ヘッダー・サイト紹介を、新しい価値提案に沿って更新。
- 大会詳細はコース地図とGPXを主役にし、取得前に作成元・対象年・算出距離を表示。対象年がない既存GPXは「未確認（参考コース）」とする。今回、GPX自体の経路修正・年度照合は行っていない。
- 大会の開催年、実際の完走タイム、本文、任意の距離地点を投稿できる。掲載種目はその大会ページの種目に固定。
- 目標タイムの前後15分に収まる完走者の体験を表示。全件表示と追加読み込みも用意。
- 地点のある体験から、参考コースの実際の幾何距離で求めた位置を地図上に表示。GPXを公称距離に引き伸ばして位置合わせはしない。
- 投稿者本人の編集・削除、ログインした利用者の通報、管理画面 `/admin/race-reviews` での非公開・再公開。
- 投稿時の問いかけは「来年この大会を走るランナーへ、あなたが伝えておきたいことは？」。
- `gpx_intent` を追加してログイン前の取得操作も計測。既存の `gpx_download` はログイン後の押下として維持。レビューの閲覧・入力開始・保存も計測し、本文はイベントに含めない。

## SEOを保つための実装

- ドメイン、URL、既存の大会slug、canonical、サイトマップ、robots、www正規化を維持。
- 大会詳細のタイトルには「試走・前日ラン」も残す。従来の説明文、周辺スポットとリンクはページ下部に保持。
- トップからの既存リンク式がすべて残ることを変更前コードと比較。検索・エリア・条件・既存スポットへの導線を維持。
- 大会ページのSSR/SSGと1時間の再検証を維持。初期レビュー本文もHTMLに含める。閲覧でログインを要求しない。
- 周辺スポット0件による大会ページの404を解消。存在しない大会slugは引き続き404。
- 投稿がない大会にレビューや評価点を捏造しない。AggregateRating構造化データを追加しない。
- ホームの既存title/description、スポット・エリア・駅ページのSEO設定は今回変更していない。

URLとコンテンツの対応、検索で読める本文と内部リンクを保つ方針は、[Google SEOスターターガイド](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)と[サイト変更時のガイダンス](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)を参照した。検索順位の維持を事前に保証するものではない。

## 本番反映時

1. 現在稼働中のCloudflareアカウント・D1・Workerとローカル設定の対応を確認する。既存 `wrangler.jsonc` のDB IDを確認せずに遠隔SQLを実行しない。
2. 対象DBのバックアップ後、`scripts/sql/2026-10-12-race-reviews.sql` を適用する。追加テーブルと索引のみで、既存データの変更・削除はない。
3. 既存のリリース手順で候補版を検証する。匿名閲覧、ログイン、投稿・編集・削除、管理画面、GPXリンク、canonical、代表的な既存スポットURL、Workerサイズを確認してから公開する。今回OpenNextのWorker生成・アップロード・本番昇格は行っていない。
4. 公開日を記録し、Search Consoleの大会ページ群と既存スポット群を分けてクリック・表示回数・CTR・掲載順位・インデックス状態を比較する。大会までの残日数と季節性を考慮する。これは運用手順であり、自動監視は設定していない。

レビューDBが利用できない場合は、体験欄に読み込み不可と再試行を表示し、大会のコース本文まで停止させない。公式GPXの供給方法・年度更新の運用は、大会への問い合わせ結果を踏まえて決める。

## 追加：地図と連動する高低図

- 大会地図の直下に、距離×標高のグラフを追加。タップ・横ドラッグ・矢印キー（100m、Shiftで1km）・Home/Endで地点を選択できる。選択地点の距離と標高を表示し、地図の黄色いマーカーと中心を移動する。「全体に戻す」で全コースへ戻る。選択ごとに地図を作り直さない。
- 元GPXの各点から累積距離・座標・標高を一緒に保持する。往路と復路を区別し、公称距離には引き伸ばさない。欠損値を0mにせず、欠損区間はグラフを切る。
- `public/race-elevation/` は静的アセット。通常ビルド時に `npm run race-elevation:build` で再生成する。GPX適用時にも生成し、原本・公開GPX・地図・高低図を同じ入力に揃える。
- 標高のない9大会は国土地理院の標高タイルから約50m間隔で地形高を取得。出典・路面高との違いを明示。DEM5A→DEM5B→DEM10B、ズーム14、対応ピクセルの値を使用し、未取得値はnull。データ・取得元URL・日時・元GPXのSHA-256を `data/race-elevation/` に保存する。元GPXが変わった場合、古い地形補完を再利用しない。地形補完はダウンロードGPXの書き換えを行わない。
- 21大会すべてに高低図。下関の地形データ1点と、さいたまGPXの18点は欠損として保持。
- 愛媛・別府大分・神戸・いびがわの大きな標高値を地形データと照合したところ、地形にも同程度の標高が存在した。標高センサー誤差と断定できないためGPXの数値は保持し、経路・標高を確認中と表示する。照合結果は `data/race-elevation/route-review.json`。公式コースとの経路照合は未完了で、高低図の実装検証と区別する。
- URL・SEOメタ情報・既存本文・内部リンクはこの追加で変更していない。
- Vitest 23ファイル92件、TypeScript、変更対象ESLint成功。21大会の静的アセットと元GPXの距離・座標の対応、地形補完のSHA-256一致も検証。板橋プレビューでクリックによる地点選択、始点・終点・100m移動、全体表示への復帰を確認。スマートフォン幅でも軸ラベルの文字サイズを保つ。
